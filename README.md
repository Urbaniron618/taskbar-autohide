# taskbar-autohide

桌面或普通窗口在前台时任务栏常显；**窗口最大化/全屏时任务栏自动隐藏**。

Windows 自带的「自动隐藏任务栏」是全局开关，TranslucentTB 只能改透明度——两者都做不到「只在最大化时隐藏」。这是个 18 KB 的小工具：**约 14 MB 内存、空闲 0 CPU、0 显存**，事件驱动，不轮询。

## 行为

| 前台窗口 | 任务栏 |
|---|---|
| 桌面（`Progman` / `WorkerW`） | 显示 |
| 普通窗口（含不可最大化的小对话框） | 显示 |
| 最大化窗口 | 隐藏 |
| 全屏窗口 / 无边框全屏（如全屏视频） | 隐藏 |
| 铺满工作区的窗口（两轴都 ≥85%，如哔哩哔哩客户端的播放页、Steam 大屏幕） | 隐藏 |
| 资源管理器文件夹窗口（explorer 按"工作区大小"重开，没有真正最大化） | 隐藏，并把窗口补满 |
| 任务栏自身、开始菜单、Alt+Tab、托盘宿主、锁屏界面 | **保持现状，不判定** |
| 工具窗口（tool window：Qt 弹窗、悬浮面板） | **保持现状**，按它所属的窗口判定 |

自动隐藏的语义：鼠标移到屏幕底边仍会划出任务栏——这是系统行为，不是漏判。

任务栏收起时工作区会变高（本机 1019 → 1067）。正常应用会自己跟着铺满，**微信不会**——它停在旧高度，屏幕底部留一条 48 px 的空桌面，鼠标一碰那条就是任务栏探出来。所以每次收起任务栏、**工作区一变高**就复核前台那个最大化窗口，没铺满就用 `SetWindowPos` 把它按到工作区上（对正常应用是空操作）；工作区还没变就隔 80 ms 再看，补完 0.7 s 再复查一次。

## 用法

直接运行 `taskbar-autohide.exe` 即可，无窗口、无托盘图标，同时只能跑一个实例（互斥锁）。

```powershell
# 安装到 %USERPROFILE%\claude-scripts 并加开机自启
.\install.ps1

# 卸载（结束进程、删除自启项、把自动隐藏恢复成关）
.\install.ps1 -Uninstall

# 手动恢复：把「自动隐藏任务栏」关掉并退出
.\taskbar-autohide.exe --off
```

自启是启动文件夹里一个 `.lnk`。取消：删掉它，或任务管理器 → 启动 → 禁用。

### 日志

每次任务栏状态变化都会记一行到 exe 旁边的 `taskbar-autohide.log`（上限 256 KB，超了自动清掉），内容长这样：

```
14:04:48.136  change on -> off: fg=Static
14:04:50.439  change off -> on: fg=Static[hidden] -> stand-in=Static[zoomed]
```

`fg=` 是判定的依据，`stand-in=` 表示前台窗口不可判定、按 z 序最上面那个可见窗口拍的板。排查「该收没收 / 该出不出」先看这个文件。

`--log` 额外记录每一个前台事件（很啰嗦，只在查问题时用）。

## 实现要点

- `SetWinEventHook` 监听 `EVENT_SYSTEM_FOREGROUND` 与前台窗口的 `EVENT_OBJECT_LOCATIONCHANGE`，替代轮询；事件到一个 45 ms 去抖（只从首个事件起算，不重置）后判定。另外挂了 `EVENT_OBJECT_HIDE` / `EVENT_OBJECT_DESTROY`（判定依据的那个窗口消失了）和 `EVENT_SYSTEM_MINIMIZEEND`（还原动画结束），用来补前台事件漏掉的那一刻。
- 判定结果通过 `SHAppBarMessage(ABM_SETSTATE)` 切换系统自动隐藏。这个调用是同步的，**会阻塞 250–530 ms**，因为 explorer 在此期间移动任务栏并更新工作区。所有判定与调用串行化，避免过期判定覆盖新判定。
- **状态从实测读取**（工作区高度 vs 显示器高度），不缓存"我上次设成什么"。explorer 重启、手动改设置、漏事件都能自愈；另有 2 秒的兜底检查。
- **前台是 shell 自己的界面时不做判定**：任务栏、开始、搜索、Alt+Tab、托盘/飞窗宿主（`Shell_TrayWnd`、`XamlExplorerHostIslandWindow` 等）。这时候用户是在操作 shell，不是在换窗口，任务栏保持原状态，等真正的窗口拿到前台自己再触发一次判定。v1.1 把这几种前台也丢进替身判定里，于是"点一下任务栏按钮"会被判成"最上面那个窗口没最大化 → 显示任务栏"，任务栏就弹出来不收了——这是 v1.2 修掉的主因。
- **前台窗口不可用时按替身判定**：前台可能是隐藏的辅助窗口（微信关掉聊天弹窗后、WPS 从任务栏激活文档时都会留一个），也可能是空。这时依次取「它归属的那个窗口（`GA_ROOTOWNER`）」→「z 序最上面那个用户看得见的窗口」→「用户上一个真正在前台的窗口」来判定；候选会跳过桌面、shell 面、隐形、最小化、cloaked 的 UWP、tool 窗口、no-activate 窗口，以及**停在屏幕外**的（`-32000,-32000` 那种，API 上全都"可见"）。
- **工具窗口（`WS_EX_TOOLWINDOW` / `WS_EX_NOACTIVATE`）拿到前台时不做直接判定**：这类窗口是弹窗、悬浮面板、托盘宿主，不是用户"在用的那个窗口"。v1.2 只看它自己是否最大化，于是微信的 Qt 弹窗（`Qt5QWindowToolSaveBits`）一露头就判成"没最大化 → 显示任务栏"，弹窗还在时任务栏会一秒一次地来回弹。v1.3 把这类前台交给替身判定，按它所属的窗口（`GA_ROOTOWNER`）算。
- **「铺满」也算最大化**：有些窗口从不调用 `ShowWindow(SW_MAXIMIZE)`，而是把自己摆成工作区大小——哔哩哔哩客户端的播放页（1707×1019 的工作区上开成 1535×1012，90%×99%）、Steam 大屏幕都是这样。只看 `IsZoomed` 会把它们当成小窗口，任务栏就压在视频上；而应用把前台从列表窗口递给播放页的那一秒里，任务栏还会先滑出来再收回去（v1.3 实测 0.4–1.4 s 的可见闪烁）。现在两轴覆盖工作区都 ≥85% 就按最大化处理（`CoversWorkArea`）。按窗口自己那块显示器的工作区算，铺到屏幕外的部分不算，所以"大但半截在屏幕外"的窗口不会被误判。
- **全屏判定留 4 px 余量**：无边框全屏窗口经常差一两个像素——Steam 大屏幕在 1707×1067 的桌面上量到 1707×1066，严格判定会说"不是全屏"，任务栏就永远压在画面上（`IsFullscreen`）。最大化窗口比显示器矮 48 px，所以 4 px 的余量不会把最大化误判成全屏。
- **资源管理器的文件夹窗口是「假最大化」**：explorer 把最大化过的文件夹窗口按**普通窗口**保存——正常矩形就是整个工作区，重开时 `showCmd=1`、`IsZoomed=false`，本机量到 1705×1017，看着满屏却没最大化。v1.4 按上面那条「铺满」判它该收任务栏，而补满（`Reflow`）只认 `IsZoomed`，于是任务栏收了、窗口却停在 1017，底下留一条 50 px 的空桌面。v1.5 给 `Reflow` 加了第二种「落伍窗口」：**窗口正好是任务栏还占着时的工作区**（工作区减掉托盘高度，容差 6 px，`SizedToWorkAreaWithTrayOut`）就补到新工作区。哔哩哔哩播放页（90% 宽、比工作区矮 7 px 以上）和副屏上的窗口都不会被误补；补满仍然只碰前台那个窗口。
- **判定的是两个状态，不是一个**：`SHAppBarMessage` 的自动隐藏状态（看工作区）和**托盘窗口实际停在哪**（看 `Shell_TrayWnd` 的矩形）可能不一致——自动隐藏开着、工作区是全高，托盘窗口却还留在屏幕上。实测：**在指针停在任务栏上时切换自动隐藏**（点任务栏按钮就是这个时机）会把托盘"卡"在屏幕里，而且 explorer 自己**永远不会**再把它收回去（stop 过 2 分钟都没动）。v1.1 只看工作区，于是认为"已经是隐藏状态，没事可做"，用户看到的就是"自动隐藏失效"。v1.2 的做法是：①指针在任务栏上时先不切，等它离开（最多 10 秒）；②每次切换后 0.5 秒复核托盘矩形，若"自动隐藏已开、指针不在任务栏、托盘仍在屏幕上并稳定 0.8 秒"就 `off → on` 重切一次——重复发同一个状态是无效的，只有关掉再打开才会移动托盘。

## 构建

不需要安装 SDK，用 .NET Framework 自带的编译器：

```powershell
.\build.ps1
# 等价于
# %SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /optimize+ /target:winexe /out:taskbar-autohide.exe taskbar-autohide.cs
```

`/target:winexe` 保证没有控制台窗口，所以登录启动时不会闪黑框，也不需要 VBS 包装。

## 实测

Windows 11 26300（1707×1067 缩放，任务栏 48 px），各测 4 轮以上：

| 指标 | 数值 |
|---|---|
| 最大化 → 任务栏消失 | 515–545 ms（其中判定约 55 ms，其余是 explorer 的固定开销） |
| 还原 → 任务栏出现 | 310–312 ms |
| 切回一个已最大化的窗口 | 438–455 ms |
| 弹出窗关掉（前台落到隐藏窗口） → 任务栏收起 | 约 800 ms（v1.0 是**永不**） |
| 点任务栏按钮打开已最大化的 WPS → 指针离开后任务栏收起 | 250–500 ms（v1.1 是**永不**：托盘被卡在屏幕上） |
| 已经卡住的托盘 → 被工具发现并收回 | 约 1.5–3 s（`off → on` 重切，含一次可见的滑动） |
| 微信最大化 → 任务栏收起后微信补满屏幕 | 约 1.4–1.7 s（任务栏先收起，0.5 s 复核时补一次 `SetWindowPos`；v1.2 是**永不**，底部留 48 px 空桌面） |
| 桌面双击文件夹（explorer 的「假最大化」窗口）→ 任务栏收起并补满 1707×1067 | 窗口出现到补满约 0.8 s，其中 explorer 收敛任务栏占 0.45 s、补满在它之后约 0.1 s（v1.4 是任务栏收了、窗口不补，底部留 48–50 px 空桌面；v1.5 之前固定多等 0.52 s） |
| 记事本等正常应用最大化 → 补满 | 0 次干预（应用自己就跟上了，复核只读不写） |
| 微信 Qt 工具弹窗拿到前台 | 0 次切换（按主窗口判定；v1.2 是每秒来回弹） |
| 哔哩哔哩客户端点视频打开播放页（列表窗口最大化） | 0 次任务栏切换（v1.3：滑出再收回，可见闪烁 0.4–1.4 s） |
| 手柄 Xbox 键打开 Steam 大屏幕 | 任务栏收起（v1.3：**永不**，任务栏压在画面上） |
| 在多个最大化应用间切换 | 0 次多余切换 |
| 正常划出/移开任务栏 | 0 次干预（指针在任务栏上时不判定、不重切） |
| 空闲 30 秒 CPU | ≈0 ms |
| 内存 | 14.3 MB（私有 9.4 MB） |
| 显存 | 0（不涉及 GPU） |

覆盖场景：资源管理器、UWP（计算器/设置）、Chrome、Edge、WPS（`OpusApp` 主窗口与其 Qt 隐藏窗口）、任务管理器、远程桌面对话框、无边框全屏、多窗口混合、托盘图标、Win+D、explorer 强制重启、锁屏与快速锁屏/解锁循环、Steam 大屏幕、哔哩哔哩客户端播放页。

.\test\popup-repro.exe small 6000        # 对照组：50%×50%，任务栏应该出来

.\test\sample-maximize.ps1 -Title 微信 -Action max   # 每 200 ms 采样，看补满的全过程

- `repro-scenario.ps1` 的 phase3 是 v1.0 的失败点：弹出窗自己消失并把前台交给一个隐藏窗口，v1.0 停在 shown 不动，v1.1 起在 1 秒内收起。
- `wedge-repro.ps1` 是 v1.2 的失败点：把指针停在任务栏上再打开自动隐藏（= 点任务栏按钮的时序），托盘就卡在屏幕里；脚本先手工造出这个状态，再启动工具，期望几秒内托盘回到屏幕外。
- `appbar-probe.exe` 单独用也能查"该收没收"：`tray=[0,1065 ...]` 表示已经收进去（只露 2 px），`tray=[0,1019 ...]` 表示在屏幕上。
- `popup-repro.exe tool` 是 v1.3 的失败点：最大化窗口在前，一个可见的 `WS_EX_TOOLWINDOW` 窗口抢到前台。v1.2 判成"没最大化"把任务栏放出来，v1.3 走替身判定，任务栏不动。
- `repro-large-window.ps1` 是 v1.4 的两个失败点，不用 Steam 和哔哩哔哩也能复现：`borderless`（无边框、显示器矮 1 px、没最大化）和 `large`（90%×99% 的工作区、没最大化）都应该让任务栏收起，`small`（50%×50%）应该让它出来。脚本会先确认前台真的是那个复现窗口，避免被别的窗口抢走焦点后误报。
- `sample-maximize.ps1` 用来量"补满"：v1.2 下微信在任务栏收起后停在 `1707x1019`，v1.3 在 1.4–1.7 s 补到 `1721x1081`；记事本在同一采样里从来不需要补。
- `repro-folder-window.ps1` 是 v1.5 的失败点，不用真的去点文件夹：`popup-repro.exe workarea` 造一个**正好工作区大小、从没最大化**的窗口（explorer 重开文件夹窗口就是这个形状）。v1.4 只收任务栏不补窗口，底部留 48 px 空桌面；v1.5 要求任务栏收起 **且** 窗口下沿贴到显示器底边（`strip<=2px`）。


## 已知限制

- 那 250–530 ms 的延迟来自 explorer，**无法从外部缩短**：关掉任务栏动画（`TaskbarAnimations`、`SPI_SETCLIENTAREAANIMATION`）、改传 `hWnd=0`、把调用挪到后台线程都实测无效。
- 工具不区分"哪个"任务栏：`ABM_SETSTATE` 只作用于主屏 appbar。接了副屏需要重测。
- 会在桌面上**主动纠正**你对"自动隐藏任务栏"的手动改动（这是设计意图）。
- 指针停在任务栏上时**不切换**自动隐藏（否则托盘会被 shell 卡在屏幕上），也就是最多晚 10 秒才切；指针一离开就立刻补上。代价是：如果你把指针一直压在任务栏上，最大化窗口会暂时按"任务栏占位"的尺寸显示。
- 托盘被卡住时靠 `off → on` 重切来救，会看到一次任务栏的滑入滑出（约 0.5 秒），且这次重切会顺手把最大化窗口的尺寸抖一下；连续 3 次救不回来就放弃，等下个 2 秒兜底周期。
- 登录时若比 explorer 先启动，首轮可能找不到任务栏句柄，2 秒内的兜底检查会补上。
- 补满只针对**已经最大化、或正好是「任务栏还占着时的工作区」**的前台窗口：一个比工作区略小、够不上 85% 的窗口不会被补，也照常显示任务栏。
- "铺满"按两轴各 85% 判定：一个手动拖到接近满屏（两轴都 ≥85%）的普通窗口也会让任务栏收起，拖小回去就恢复。
- 「比工作区略小」的窗口本身不会被放大：工具只补两种——已经最大化的，和正好是「任务栏还占着时的工作区」的（v1.5，资源管理器文件夹窗口）。哔哩哔哩的播放页是客户端自己摆的 1535×1012，比工作区矮 7 px 以上，不在补的范围内；v1.4 起只保证任务栏不再压在它上面、也不再闪。

## 变更记录

**v1.5.1** — 补满不再固定等半秒：

- 实测 `SHAppBarMessage` **返回时工作区已经变大了**（本机几次调用 53 / 451 / 476 ms，都是返回即生效），v1.5 却固定等 520 ms 才复核——那半秒里窗口还停在旧高度，底下露着空桌面。
- 现在切成「收」之后 90 ms 就复核；工作区若还没动就每 80 ms 再试（最多 700 ms，接口有可能先返回）；补完仍然 700 ms 后再复查，答复得晚的应用照样会被补。
- 实测：桌面双击文件夹，窗口出现到补满从约 1.1 s 降到约 0.8 s（explorer 自己收敛任务栏的 0.45 s 是下限）；`popup-repro workarea` 下补满和任务栏动画几乎同时结束。

**v1.5** — 修「点击桌面上的文件夹，窗口不最大化、任务栏收了却留着底部一条」：

- **资源管理器的文件夹窗口是「假最大化」**：explorer 把最大化过的文件夹窗口按普通窗口保存——正常矩形就是整个工作区，重开时 `showCmd=1`、`IsZoomed=false`，本机量到 1705×1017（工作区 1707×1019），看着满屏其实没最大化。v1.4 的「铺满 ≥85%」判它该收任务栏，但补满（`Reflow`）只认 `IsZoomed`，于是任务栏收起了、窗口停在 1017，屏幕底部留一条 50 px 的空桌面——鼠标一碰那条任务栏就探出来，看着就像"没最大化"。
- 现在 `Reflow` 多认一种「落伍窗口」：**窗口正好是任务栏还占着时的工作区**（工作区高度减去托盘高度，容差 6 px，`SizedToWorkAreaWithTrayOut`），就按新工作区补一次 `SetWindowPos`。判定用几何、不看 `IsZoomed`，所以 explorer 这种"没真的最大化"的窗口也能补；只算主屏（`ABM_SETSTATE` 只管主屏任务栏），哔哩哔哩播放页那种「比工作区小一截」的窗口不在范围内。
- 实测：桌面双击文件夹 → 约 0.8 s 后窗口从 1705×1017 补到 1707×1067，任务栏保持收起，底部不再留空桌面。
- 测试：`test\popup-repro.cs` 加 `workarea` 模式（正好工作区大小、没最大化，不用真的开资源管理器），新增 `test\repro-folder-window.ps1`——同时校验"任务栏收起"和"窗口补满、底部不留条"。

**v1.4** — 修两个「窗口铺满屏幕、任务栏还在（或者闪一下）」的场景：

- **哔哩哔哩客户端点视频打开播放页，任务栏滑出来再收回去**：客户端把前台从列表窗口递给自己的播放页，播放页是**普通窗口**——本机工作区 1707×1019 上开成 1535×1012（90%×99%），从不 `SW_MAXIMIZE`。v1.3 只看 `IsZoomed` → 判成"小窗口" → 任务栏滑出来压在视频上，随后列表窗口回到前台又收回去；实测这一下闪 0.4–1.4 s（取决于播放页加载快慢）。现在**两轴覆盖工作区都 ≥85% 的窗口按最大化判定**，整个切换过程任务栏不动；播放页留在一屏时任务栏也保持收起。
- **手柄 Xbox 键打开 Steam 大屏幕，任务栏不隐藏**：大屏幕是无边框窗口，本机量到 1707×1066，比显示器（1707×1067）矮 1 px，严格的"盖住显示器"判定判成非全屏。现在 `IsFullscreen` 允许 4 px 余量——最大化窗口比显示器矮 48 px，不会被误判成全屏。
- 测试：`test\popup-repro.cs` 加 `borderless` / `large` / `small` 三个模式（不需要 Steam 和哔哩哔哩），新增 `test\repro-large-window.ps1` 一次跑完三条并给出 PASS/FAIL。

**v1.3** — 修微信（4.1.13，Qt 5.15.14）上的两个问题：

- **最大化后底下留一条任务栏**：任务栏一收起工作区就从 1019 涨到 1067，explorer 不会替你重新最大化——正常应用（记事本实测）自己跟上去，微信不跟，停在 `1707x1019`，屏幕底部留 48 px 空桌面，鼠标一碰那条任务栏就探出来，看着就是"没最大化"。再发一次 `SC_MAXIMIZE` 微信不理会，只有 `SetWindowPos` 到工作区能挪动它。现在每次收起任务栏后 0.5 秒复核前台那个最大化窗口，没铺满就补一次；只碰最大化窗口、只补前台那个，正常应用是空操作。
- **Qt 工具窗口抢前台导致任务栏来回弹**：微信的 `Qt5QWindowToolSaveBits` 弹窗可见时能拿到前台，v1.2 按它自己的小尺寸判定 → "没最大化" → 放任务栏；前台回到主窗口又收起，一秒一个来回。现在 `WS_EX_TOOLWINDOW` / `WS_EX_NOACTIVATE` 的前台不做直接判定，走替身路径按它所属的窗口算（`IsUserWindow` 本来就拒绝挑这类窗口，两处现在一致了）。
- 测试：`test\popup-repro.cs` 加 `tool` 模式（不用微信就能造出第二个失败点），新增 `test\win-state.ps1` 与 `test\sample-maximize.ps1`（逐帧量补满过程）。

**v1.2** — 修「自动隐藏失效」的真正机制：**自动隐藏状态已经是"隐藏"，托盘窗口却还停在屏幕上**（工作区是全高，所以 v1.1 认为没事可做，永远不纠正）：

- 触发条件实测确定：**在指针停在任务栏上时**把自动隐藏切成"开"（点任务栏按钮打开一个已最大化的窗口，就是这个时序），托盘会被 shell 卡在屏幕里；之后 explorer 自己**不会**再收回它。v1.1 点一次任务栏按钮就会踩中，微信等弹窗关闭时的状态切换也可能踩中。
- 现在判定两个状态：appbar 状态（工作区）**和**托盘窗口矩形。切换后 0.5 秒复核；若"自动隐藏开着、指针不在任务栏、托盘还在屏幕上且位置稳定 0.8 秒"，就用 `off → on` 重切一次把托盘推回去（重复发同一状态无效，实测）。
- 指针在任务栏上时**先不切**，等指针离开再切（250 ms 轮询，最多 10 秒），从源头避免上面那个卡位。
- 前台是 shell 自己的界面（任务栏、开始、搜索、Alt+Tab、托盘飞窗）时**不做判定**，保持现状——README 一直是这么写的，v1.1 的代码却把这些前台也丢进了替身判定，于是点任务栏会误判成"最上面那个窗口没最大化 → 显示任务栏"。
- 替身判定的顺序改为：窗口归属（`GA_ROOTOWNER`）→ z 序最上面 → 用户上一个真实前台；候选新增「停在屏幕外」过滤（`-32000,-32000` 那种辅助窗口 API 上是可见的，v1.1 会把它当成用户眼前那个窗口）。
- 测试：新增 `test\appbar-probe`（量测）、`test\wedge-repro.ps1`（卡位回归）、`test\repro-taskbar-click.ps1`（真点任务栏按钮）；修好 `popup-repro focus` 的参数解析 bug。

**v1.1** — 修两类「自动隐藏失效」：

- 微信等应用弹出窗消失后任务栏不收回：弹窗关掉时微信把前台交给了自己的**隐藏辅助窗口**，v1.0 对不可见的前台一律「不判定」，于是停在弹窗期间的那个"任务栏常显"状态上。现在按 z 序取最上面的可见窗口判定（stand-in）。
- 通过任务栏打开 WPS 已打开文件后任务栏不收回：同一种前台状态，只是触发源是 explorer 激活 + WPS 的 Qt 辅助窗口。同一处修复覆盖。
- 补挂 `EVENT_OBJECT_HIDE` / `EVENT_OBJECT_DESTROY` / `EVENT_SYSTEM_MINIMIZEEND`，判定依据的窗口消失或还原结束时立刻重判，不用等 2 秒兜底。
- 日志改为决策级常开（几行/次状态变化），`--log` 才记全部前台事件。

**v1.0** — 首版：最大化/全屏时收起任务栏，其余时候常显。
